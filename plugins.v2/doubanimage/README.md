# 豆瓣通知图片代理

自动把 MoviePilot 通知里的**豆瓣海报地址**改写成本机自建代理地址，解决企业微信／微信图文消息的**封面裂图、空白**问题；竖版海报还会自动处理成 16:9 横图，避免被企业微信从正中裁掉人物。

豆瓣 CDN 对不带 Referer 的请求一律返回 418，而企业微信的封面是由它的服务器主动抓取的（不带 Referer），所以直接把豆瓣原图地址塞进 `picurl` 一定显示不出来。

---

## 功能

| 能力 | 说明 |
|---|---|
| 地址改写 | 通知发送前经 `post_message` 钩子，把豆瓣图片地址换成 MP 自建代理地址 |
| 免登录代理 | 代理接口匿名开放，服务端补 Referer 取图，webp 统一转 JPEG |
| 竖版转横版（A） | 用通知标题反查豆瓣条目，有官方横版剧照就换成 16:9 的那张 |
| 竖版转横版（B） | 没有横版剧照时，代理端把竖图按上部裁成 16:9 |
| 抗风控 | 豆瓣镜像子域轮换（img1/2/3/9 + jpg/webp）、请求节流 250ms、418 单独识别 |
| 可选 Cookie | 豆瓣风控严重时填自己的 Cookie，只发给搜索/剧照接口，不发往图片 CDN |
| 诊断 | `/stat` 接口查看抓取日志与命中情况 |

> 不依赖 `mediainfo`：MP 的 `post_message` 钩子只传 message，v1.4 起改为从通知标题反查条目，不再踩这个坑。

---

## 快速开始

### 1. 前提：代理地址要能被企业微信服务器访问

封面是**企业微信服务器主动来抓**的，所以 MP 的代理地址必须是公网可达的域名（例如你自建的 `https://mp.xxx.xxx:端口`），不能是 `127.0.0.1` 或纯内网 IP。

### 2. 安装启用

在 MP 外部插件仓库 `https://github.com/celestial520/mp-plugins.git` 里安装「**豆瓣通知图片代理**」→ 启用 → 按下面配置 → 保存。

### 3. 配置项

| 配置 | 说明 | 建议 |
|---|---|---|
| 启用插件 | 总开关 | 开 |
| 竖版封面自动转横版 | 竖图统一裁成 16:9 | 开 |
| 优先使用豆瓣横版剧照 | 先找官方横图，找不到才裁剪 | 开 |
| 豆瓣 Cookie（可选） | 风控严重时填，只用于搜索/剧照接口 | 一般留空 |

### 4. 验证

触发任意一条带豆瓣海报的 MP 通知，看企业微信里的封面是否显示；显示异常时访问插件的 `/stat` 诊断接口看抓取日志。

## 原理

```
MP 准备发通知（picurl = 豆瓣原图）
        ↓  post_message 钩子
① 用通知标题反查豆瓣条目 → 有官方横版剧照就换上（A）
② 改写 picurl 为 MP 自建代理地址，并带版本参数绕过企微抓图缓存
        ↓  企业微信服务器来抓图
代理接口：补 Referer → 镜像子域轮换 → webp 转 JPEG
③ 兜底：任何竖图按上部裁成 16:9（B），即使参数丢失也不会被正中裁
```

代理接口额外支持 `HEAD` 方法——企业微信抓图前会先发 HEAD 探测，v1.0 返回 405 正是当时封面空白的原因。

## 常见问题

**Q：封面还是空白？**
按顺序查：① 代理地址是否公网可达；② MP 的站点域名/端口配置是否正确；③ `/stat` 里有没有抓取记录、是不是 418/502。

**Q：返回 418？**
豆瓣风控。插件会自动轮换镜像子域并节流；如果仍频繁命中，在设置里填豆瓣 Cookie（只在搜索/剧照接口使用）。

**Q：竖版海报被裁得只剩中间？**
确认「竖版封面自动转横版」已开；插件默认按**上部**裁剪，而不是居中裁。

**Q：通知本身没有图片怎么办？**
插件会回退取媒体图；都没有就不带封面，不影响文字通知。

**Q：会不会把 Cookie 发到图片 CDN？**
不会。Cookie 只用于豆瓣搜索与剧照接口，图片请求只补 Referer 和 Accept-Language。
