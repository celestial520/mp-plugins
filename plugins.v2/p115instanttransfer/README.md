# 115秒传监控（MoviePilot 插件）

监控一个本地文件夹，发现媒体文件后自动验证能否在 **115 网盘「秒传」**：

- **能秒传** → 立即秒传（零带宽），成功后把源文件移入【回收目录】，并发送微信通知
- **不能秒传** → 拦截（不上传任何字节），记入待重试列表，次日同一时间再次验证
- **连续失败超过设定天数仍无法秒传** → 放弃（移出待重试，可选通知）

## 需求对照

| 你的要求 | 实现方式 |
|---|---|
| 监控某个文件夹 | 定时（默认每 1 小时）递归扫描「监控文件夹」 |
| 验证是否能秒传 | 计算文件 SHA1 + 大小，调用 `client.upload_file_init(...)`，看返回 `reuse` 是否为真 |
| 不能秒传就拦截 | `reuse` 为假时只取预上传信息、**不会真正上传任何字节**，文件原样保留并记入待重试 |
| 第二天再次验证 | 每日「重试小时」（默认 3 点）的 cron 任务重新验证待重试列表 |
| 能秒传了再传 | `reuse` 为真即秒传成功（文件瞬间存在于 115，零带宽） |
| 传完发微信通知 | 走 MP 内置通知 `CommandChian().post_message(Notification(...))`，复用你已配好的微信/企业微信渠道 |
| 自动删除源文件 | 秒传成功后把源文件**移入回收目录**（你选的方案），你定期清理即可 |

## 安装

### 方式一：MP 插件市场添加插件合集仓库（推荐）

本插件已合并进 [mp-plugins](https://github.com/celestial520/mp-plugins) 插件合集，仓库地址：

```
https://github.com/celestial520/mp-plugins.git
```

1. MP →【插件】→ 插件仓库／设置 → 添加外部插件仓库，粘贴上面的地址并保存。
2. 刷新插件列表，在「未安装」里找到「**115秒传监控**」，点安装。
3. 启用插件，填写下方配置项并保存。微信通知会自动走你在 MP【设定 - 通知】里已配好的渠道。

### 方式二：手动安装

把 `plugins.v2/p115instanttransfer` 整个目录复制到 MoviePilot 的 `app/plugins/` 下
（绿联 NAS Docker 部署时，通常是 config 映射目录里的 `plugins/`，容器内对应 `/app/app/plugins/` 或 `/config/plugins/`），
然后重启 MoviePilot 即可。

## 配置项

| 配置 | 说明 | 默认 |
|---|---|---|
| 启用插件 | 总开关 | 关 |
| 微信通知 | 秒传成功/放弃时是否发通知 | 开 |
| 监控文件夹路径 | 放待传媒体文件的目录 | 空 |
| 回收目录 | 秒传成功后源文件移入这里 | 空 |
| 115 Cookie | `UID=...;CID=...;SEID=...;KID=...`（浏览器登录 115 后从 Cookie 取） | 空 |
| 115 目标目录 CID | 传到 115 的哪个文件夹，`0` = 根目录（填 115 网盘 URL 里的 `cid`） | 0 |
| 媒体扩展名 | 逗号分隔，只处理这些后缀 | mp4,mkv,mov,iso,ts,m2ts,avi,rmvb,flv,wmv,m4v |
| 最小大小(MB) | 0 = 不限制 | 0 |
| 扫描间隔(小时) | 周期性扫描频率 | 1 |
| 每日重试小时(0-23) | 次日重试的时间点 | 3 |
| 放弃天数(0=永不) | 连续失败多少天后放弃 | 0 |

## 命令

在微信 / MP 私聊里发送：

```
/p115_status
```

可查看当前监控目录、待重试文件数、已放弃数、累计秒传成功数。

## 依赖

- `p115client`（见本插件目录 `requirements.txt`）

若插件加载报 `No module named p115client`，进 MP 容器执行 `pip install p115client` 即可
（若装过「115 网盘 STRM 助手」等插件通常已自带该依赖）。

## 原理说明

115 秒传依赖文件哈希已存在于网盘。`upload_file_init(filename, filesize, filesha1, pid)` 返回的
`reuse` 为真即代表「文件已瞬间存在于网盘」——这一步**不消耗任何上传带宽**，因此：

- 验证能否秒传 = 调一次该接口看 `reuse`
- 不能秒传时天然实现「拦截」（不会真正上传字节）
- 能秒传的那一刻，文件已经落到 115，然后插件把本地源文件移入回收目录并通知

某些文件始终无法秒传，说明它还没被别人传到 115——这正是「拦截 + 次日重试」的意义。
