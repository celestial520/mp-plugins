# 115秒传搬运（MP 插件版）

监控一个本地目录，白名单内文件先验证 **115 网盘能否「秒传」**：能就直接在网盘创建文件（不占上行带宽）、发通知、可选删除源文件；不能就**原样保留、不上传任何字节**，到第二天设定的时间再验证，直到能秒传为止。

复用 MoviePilot 里已经授权的 115 开放平台存储实例（`U115Pan`），**插件不保存、不搬运任何 115 凭据**。

---

## 功能

| 能力 | 说明 |
|---|---|
| 秒传验证 | `POST /open/upload/init`，用全量 SHA1 + 前 128MB SHA1 判断服务端是否已有相同内容 |
| 不占带宽 | 只验证不上传；秒传命中时网盘侧直接创建文件 |
| 二次认证 | 遇到 700/701 `sign_check`，按官方要求计算区间 SHA1 后重新 init，提高命中率 |
| 三种触发 | 下载器完成 / 文件变化实时事件 / 每日定时巡逻 |
| 不能秒传时 | 拦截并保留源文件，次日指定时间重试；可选改为真实上传 |
| 删源控制 | 「秒传成功后删除本地源文件」独立开关，与秒传语义解耦 |
| 空文件夹清理 | 每天定时清理，绝不删除监控目录本身 |
| 通知 | 走 MP 内置渠道，成功/被拦截都可推送 |
| 立即运行一次 | 插件动作手动触发一轮 |
| 大文件优化 | 4MB 分块单遍同时算全量与前 128MB SHA1，不读两遍盘 |

## 快速开始

### 1. 前提

- MP 里已授权「115 开放平台（OpenAPI）」存储；
- 监控目录已挂进 MP 容器，容器内路径与设置页填写的一致。

### 2. 安装启用

在 MP 外部插件仓库 `https://github.com/celestial520/mp-plugins.git` 里安装「**115秒传搬运**」→ 启用 → 配置 → 保存 → 点「立即运行一次」验证链路。

### 3. 配置项

| 配置 | 说明 |
|---|---|
| 启用插件 | 总开关 |
| 本地监控目录 | 容器内路径，可下拉选也可手填 |
| 115 目标目录 | 网盘目标 CID |
| 秒传成功后删除本地源文件 | 关 = 保留源文件（做种/给下游用） |
| 不能秒传时改为真实上传 | 关 = 只做秒传，不占上行带宽 |
| 扩展名白名单 / 体积下限 | 只处理符合条件的文件 |
| 巡逻间隔（分钟） | 周期性扫描频率 |
| 文件稳定（分钟）/ 文件写入静置（秒） | 避免把还在下载/写入的文件传走 |
| 不能秒传时，第二天几点再检测 | 拦截文件的重试时间点 |
| 每天清理空文件夹 / 几点清理 | 监控目录本身始终保留 |
| 目录监控 / 下载器监控 / 递归扫描子目录 | 三种触发分别开关 |
| 发送微信通知 / 文件被拦截时也通知 | 走 MP 已配好的通知渠道 |

> 监控目录在 **SMB / NFS 网络共享**上时，远端变化不会通知容器，inotify 收不到；这时关掉「目录监控」，只靠下载器监控 + 每日巡逻。

## 触发方式

| 优先级 | 触发 | 场景 |
|---|---|---|
| 1 | 下载器监控 | Transmission / qB 任务完成，立即处理该任务的文件 |
| 2 | 目录监控（inotify） | 目录里出现新文件、且写入静置结束后 |
| 3 | 每日定时巡逻 | 兜底，并把昨天拦截的文件重新验证一遍 |

三种触发都按**路径归属**分发：文件落在监控目录内才处理。下载器只认已完成任务，`.part` / `.!qB` / `.crdownload` 等临时后缀直接跳过。

## 秒传流程

```
本地文件 → 计算 SHA1 + 前128MB SHA1 → /open/upload/init
   ├─ data.status == 2（命中）  → 网盘文件已创建 → 通知 → 可选删源
   ├─ 700/701 sign_check       → 补算区间 SHA1 后重新 init
   └─ 未命中                   → 不上传任何字节 → 记入拦截 → 次日指定时间再验证
```

新资源第一次基本都命中不了，等 115 上已有完全相同内容（或你自己传过）后，下次扫描就会秒传成功——这正是「拦截 + 次日重试」的意义。

## 常见问题

**Q：一直「暂不能秒传」是不是坏了？**
不是。秒传取决于服务端是否已有相同内容，新资源第一次大多失败，次日会自动重试。

**Q：MP 里要不要重新登录 115？**
不用。插件直接复用 MP 内置的 `U115Pan` 实例和已授权令牌。

**Q：下载目录的文件被删了，影响做种吗？**
会。所以下载目录那条任务把「秒传成功后删除本地源文件」关掉。

**Q：一部 20GB 电影真实上传会怎样？**
实打实占 20GB 上行带宽。为了省带宽保持「不能秒传时改为真实上传」关闭。

**Q：和 `115秒传监控` 插件冲突吗？**
别让两个插件监控同一个目录，会抢文件。新装建议只用本插件。

**Q：和独立的 `115-rapid-upload`（带 WebUI 的 Docker 版）什么关系？**
那个是独立项目，自带网页和扫码登录；本插件是 MP 内的版本，复用 MP 的 115 授权和通知渠道。二选一。
