# 115秒传助手 · 整理通知

> ⚠️ **已弃用，建议卸载**：115秒传助手已经移除外部触发接口，本插件的推送会失败。助手现在靠文件变化事件（inotify）自动发现 MP 整理进监控目录的文件，**不需要插件配合**。清单里保留该条目仅作记录。

原先的作用：MoviePilot 整理完成后，把整理出来的**真实目标路径**直接推给 115秒传助手，让它立刻尝试秒传，不用等自己的每日扫描。

MP 整理会把文件从下载目录搬到媒体库，助手按自己的监控目录去找是找不到的，所以当时必须把整理后的路径带过去。

## 功能（历史）

| 能力 | 说明 |
|---|---|
| 整理事件监听 | `TransferComplete` / `SubtitleTransferComplete` / `AudioTransferComplete` |
| 路径映射 | MP 容器内路径 → 助手容器内路径，每行一条 |
| 推送目标 | 可推「整理后的文件夹」或「文件清单」 |
| 去重 | 60 秒内相同批次只推一次 |
| 鉴权 | 请求带 `X-API-Key` |
| 通知 | 可选推送后在 MP 里也发一条 |

## 快速开始

**现在不需要安装。** 如果你还在用本插件：

1. 在 MP 插件页**卸载 / 禁用**「115秒传助手·整理通知」。
2. 确认 115秒传助手（Docker 版或 MP 插件版）的监控目录指向 MP 整理后的目录。
3. 打开助手的**文件变化实时触发**（inotify）；目录在 SMB / NFS 网络共享上时改靠下载器监控 + 每日定时扫描。

助手会自己发现新文件，无需 `/api/trigger` 推送。

### 历史配置项（仅作参考）

| 配置 | 说明 |
|---|---|
| 启用插件 | 总开关 |
| 115秒传助手地址 | 例如 `http://192.168.1.10:9191` |
| API Key | 助手网页「外部触发」里复制 |
| 路径映射 | `MP路径 => 助手路径`，两边路径不一样时才填 |
| 推送什么给助手 | 文件夹 / 文件清单 |
| 推送整批文件 / 字幕音轨也推送 | 范围开关 |
| 请求超时（秒） | 默认 60 |
| 推送后在 MP 里也发通知 | 走 MP 内置渠道 |

## 为什么被弃用

```
旧链路：MP 整理完成事件 → 本插件 POST /api/trigger → 助手开始秒传
新链路：MP 把文件移进监控目录 → 助手 inotify 发现 → 直接秒传
```

助手移除外部触发接口后，旧链路的请求会失败或无人响应；而文件变化事件已经覆盖了同样的场景，还少一层路径映射配置。

## 常见问题

**Q：插件还在推、日志报错，要紧吗？**
不影响 MP，但都是无效请求。直接卸载/禁用即可。

**Q：不装插件，助手还能发现 MP 整理的文件吗？**
能，前提是把助手的监控目录设成 MP 整理后的目录，并打开实时触发。

**Q：监控目录是网络共享，收不到文件变化怎么办？**
关掉实时触发，用「下载器监控 + 每天定时扫描」兜底。

**Q：这个插件以后会删掉吗？**
清单条目暂时保留，避免老配置找不到插件导致 MP 报错；不会继续更新功能。
