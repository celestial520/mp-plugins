# WorkBuddy 每日签到（MoviePilot 插件）

让 WorkBuddy 的**每日积分**在 MoviePilot 里自动领：MP 常开就常领，长效令牌自动续期，断签、MP 重启、升级后都能补上，不用开电脑、不用再起一个 Docker 容器。

签到成功走 **MP 内置消息渠道**通知（`CommandChain.post_message`），直接复用你在 MP【设定 → 通知】里已经配好的企业微信／微信，**不用在插件里填 corpid、Secret、AgentId**。

---

## 功能

| 能力 | 说明 |
|---|---|
| 每日签到 | 每天 100 积分，连签第 7 天 1000 分（以官方活动显示为准） |
| 令牌自续期 | 刷新令牌每次轮换后回写 MP 插件数据，正常情况下只填一次 |
| 断签补签 | 每天定时 + 周期补签双任务；MP 重启后开机自动补 |
| 幂等 | 先查状态，今天领过就跳过；接口返回「已签到」也当成功，不会重复发分 |
| 成功通知 | 走 MP 已配好的企业微信/微信渠道，纯文本，附带连签天数和本期累计 |
| 失败提醒 | 可选，每天最多一次；令牌失效时告诉你去重新导出 |
| 异常隔离 | 签到全流程 try/except，出问题只写 MP 日志，绝不影响 MP 主进程 |
| 零额外依赖 | 只用 `requests`（MP 自带）+ 标准库，不需要 pip 装东西 |

> 和独立 Docker 版是**二选一**：两个同时跑不会重复发分（幂等），但会各自轮换令牌，没必要。用这个插件就够了。

## 快速开始

### 1. 先拿到长效令牌（一次性，Windows 上做）

客户端 5.6.2 之后登录态是 AES-256-GCM 加密信封，token 不能手抄。在**已登录 WorkBuddy 的 Windows 电脑**上，下载 [mp-plugins](https://github.com/celestial520/mp-plugins) 仓库 ZIP（或 clone），在仓库根目录双击：

```
tools/export_token.bat
```

生成 `data/refresh_token`（明文不会显示在屏幕上）。这一步绕不开：MP 跑在 NAS 上，没有 WorkBuddy 客户端，解不了本机登录态。

> 导出工具用 `WorkBuddy.exe` 自身的 Node 模式读取客户端运行时密钥并本地解密，**只读**登录态文件，不修改、不上传任何内容。
> 工具在**仓库根目录 `tools/`** 下；插件市场安装只会拉插件目录本身，所以这一步需要单独下载仓库。

### 2. 安装插件

**方式一：MP 插件市场添加插件合集仓库（推荐）**

插件合集仓库地址（添加一次，合集里所有插件都能装）：

```
https://github.com/celestial520/mp-plugins.git
```

1. MP →【插件】→ 插件仓库／设置 → 添加外部插件仓库，粘贴上面的地址并保存。
2. 刷新插件列表，在「未安装」里找到「**WorkBuddy每日签到**」，点安装。
3. 启用插件，按下面第 3 步填配置。

**方式二：手动安装**

把 `plugins.v2/workbuddycheckin` 整个目录复制到 MoviePilot 的 `app/plugins/` 下
（绿联 NAS Docker 部署时，通常是 config 映射目录里的 `plugins/`，容器内对应 `/app/app/plugins/` 或 `/config/plugins/`，以你 compose 的实际挂载为准），然后重启 MP。

> 插件只用 `requests`（MP 自带）和 Python 标准库，不需要进容器 `pip install`。

### 3. 填插件设置页

| 必填 | 值 |
|---|---|
| 启用插件 | 打开 |
| 长效令牌 refresh_token | 粘贴第 1 步导出的那一长串 |
| 签到成功通知 | 打开（默认） |

其余保持默认即可：`接口域名 = www.workbuddy.cn`、`每日执行时间 = 09:00`、`失败重试间隔 = 30` 分钟。

> MP 里配过企业微信通知的话，到这一步就已经能收到消息了；插件不碰企业微信的 corpid / Secret / AgentId。

### 4. 验证

在微信 / MP 私聊里发：

```
/wb_test
```

收到「【测试消息】WorkBuddy 每日签到插件通知链路正常。」就说明通知通了。再发 `/wb_checkin` 立即跑一次，`/wb_status` 看状态。

## 配置项

| 配置 | 说明 | 默认 |
|---|---|---|
| 启用插件 | 总开关 | 关 |
| 签到成功通知 | 真正领到积分时推送 | 开 |
| 失败也通知 | 失败时每天最多推一次，提醒令牌失效 | 开 |
| 已签到也通知 | 今天手动领过、插件跳过时也推一条 | 关 |
| 长效令牌 refresh_token | 第 1 步导出的令牌；只在首次或重新导出时填 | 空 |
| 接口域名 | 签到 / 刷新接口域名，一般不用改 | `www.workbuddy.cn` |
| 每日执行时间 | 北京时间 HH:MM | `09:00` |
| 失败重试间隔(分钟) | 补签轮询间隔，最小 5 | `30` |

## 通知

复用 MP 的 `CommandChain().post_message(Notification(...))`，也就是你在 MP【设定 → 通知】里已经配好的企业微信、微信、Telegram 等渠道；**插件不需要也不保存任何企业微信凭据**。

签到成功的消息长这样（纯文本，markdown 在微信端不渲染）：

```
WorkBuddy 每日签到助手：今日积分已到账
【签到成功】+100 积分
· 连签 13 天
· 本期累计 1300 分
· 时间 2026-11-07 09:00:01

明天 09:00 继续自动领。
```

失败通知会带上原因，例如「刷新令牌失败 …（多半是令牌失效，请重新导出一次）」。

| 想做什么 | 怎么做 |
|---|---|
| 测试通知链路 | `/wb_test` 或插件 API `/test-notify` |
| 只看成功、不要失败消息 | 关掉「失败也通知」 |
| 企业微信报 60020 | 出口 IP 不在应用可信 IP 里，去企业微信后台加白名单（MP 侧通知配置问题，与插件无关） |

## 令牌是怎么来的

```
WorkBuddy 客户端登录态（AES-256-GCM 加密信封）
        ↓  tools/export_token.cjs（Windows 上用客户端运行时密钥本地解密）
插件设置页里的 refresh_token
        ↓  插件首次运行
官方网关 /v2/plugin/auth/token/refresh → 新 access_token + 轮换出的新 refresh_token
        ↓  立刻写回 MP 插件数据（PluginDataOper，"state"）
/v2/billing/meter/checkin-activity-status → /daily-checkin
```

- **设置页里那把令牌只是「初始令牌」**。之后插件一直用插件数据里轮换后的新令牌，不用反复粘贴。
- 你在设置页重新粘贴一把新令牌时，插件会比对指纹并自动切换到新令牌，所以令牌失效后重新导出、重新粘贴即可。
- 只有**退出登录 / 改密码 / MP 插件数据被清空**才会失效，届时失败通知会提醒你。
- 接口返回 `code=10001`（今天已签到，请明天再来）按成功处理，不重复发分。

> refresh_token 等同账号钥匙：会以明文存在 MP 的插件配置 / 插件数据里。别把填写过的配置截图外发，别把它写进 README 或提交到仓库。

## 每天什么时候领

插件注册两个 MP 定时服务，都调同一个幂等入口：

| 服务 | 触发 | 作用 |
|---|---|---|
| WorkBuddy 每日签到 | cron，每天 `check_at`（默认 09:00） | 正常领 |
| WorkBuddy 签到补签 | interval，每 `retry_minutes` 分钟 | 失败重试、MP 重启/升级后补签 |

时间按 **UTC+8** 计算，不依赖 MP 容器时区。今天已经成功（插件领的或你手动领的）就当天不再请求，等明天。

## 常见问题

**Q：还要不要开 WorkBuddy 客户端？**
不用。插件用的是长效令牌，直接调官方接口，客户端关着也能领。

**Q：令牌失效了怎么办？**
在 Windows 上重新双击 `tools/export_token.bat`，把新令牌粘贴回插件设置页并保存，插件会自动切过去。退出登录、改密码后基本都要做一次。

**Q：MP 重启 / 升级会不会断签？**
会补。插件加载后补签任务发现今天还没成功且已过执行时间，立即补领。MP 升级后如果插件 API 有变动，可能需要同步更新插件。

**Q：已经在客户端手动领过了，插件还会领吗？**
不会，先查状态，`today_checked_in=true` 直接跳过；默认也不发「已签到」通知。

**Q：收不到企业微信通知？**
先发 `/wb_test`。收不到说明是 MP 侧通知渠道没配好（去【设定 → 通知】检查），不是插件问题；插件还有兜底，会把消息写进 MP 系统消息。

**Q：日志里报「刷新令牌失败」？**
多半是令牌过期或会话被踢，按第一条重新导出。若报网络类错误，检查 MP 容器能否访问 `www.workbuddy.cn`。

**Q：日志说活动未开放？**
本期签到活动下线或尚未开始，当天跳过，明天自动再试。积分规则、奖励数额以客户端实际显示为准。

**Q：和之前的 Docker 版冲突吗？**
不会重复发分，但两边会各自轮换令牌。建议只留一个：用插件就把 Docker 容器停掉。

| 位置 | 内容 |
|---|---|
